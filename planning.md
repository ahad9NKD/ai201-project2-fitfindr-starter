### Tool 1: search_listings

**What it does:**
Searches the mock marketplace listings and returns the best matches for a shopping request. It filters the loaded listings by the user’s search description, requested size, and maximum price, then ranks the remaining results by how closely the title, description, category, style tags, colors, brand, and platform align with the request.

**Input parameters:**
- `description` (str): The user’s shopping request or item description, such as `"vintage graphic tee"`.
- `size` (str): The desired clothing size to match against the listing’s `size` field, such as `"M"` or `"US 7"`.
- `max_price` (float): The highest price the user is willing to pay; listings with `price` greater than this value are excluded.

**What it returns:**
A list of matching listing dictionaries sorted from most relevant to least relevant. Each listing includes `id`, `title`, `description`, `category`, `style_tags`, `size`, `condition`, `price`, `colors`, `brand`, and `platform`, so the agent can display the item and pass the selected listing into `suggest_outfit`.

**What happens if it fails or returns nothing:**
If no listings match the filters, the agent stops the interaction immediately, tells the user that nothing matched, and suggests broadening the search by relaxing the size, price, or description. It does not call `suggest_outfit` or `create_fit_card` with an empty result.

---

### Tool 2: suggest_outfit

**What it does:**
Generates an outfit suggestion using the selected new listing and the user’s wardrobe. It looks for complementary wardrobe items by category, color, and style tags, then returns styling advice in plain language with at least one specific pairing and one styling tip.

**Input parameters:**
- `new_item` (dict): The selected listing dictionary returned by `search_listings`, including the item the user wants to buy.
- `wardrobe` (dict): A wardrobe object in the `{"items": [...]}` format from `data/wardrobe_schema.json`, containing the user’s existing clothes and accessories.

**What it returns:**
A single outfit suggestion string, such as `"Pair this with your wide-leg jeans and platform Docs for a classic 90s grunge look. Roll the sleeves once and tuck the front corner slightly for shape."` The returned text should reference specific wardrobe items when possible and explain why the combination works.

**What happens if it fails or returns nothing:**
If `wardrobe.items` is empty, the agent returns a friendly message that it cannot suggest a full outfit yet and should ask the user to add wardrobe items first. If the wardrobe exists but no useful pairing can be found, the agent should still return a fallback styling note that uses the new item alone, or stop with a clear explanation rather than passing `null` into `create_fit_card`.

---

### Tool 3: create_fit_card

**What it does:**
Turns the outfit suggestion into a short shareable fit-card caption. It combines the new item’s basic details with the styling language from `suggest_outfit` and produces a social-ready sentence or two that sounds like a post caption.

**Input parameters:**
- `outfit` (str): The styling sentence or caption generated by `suggest_outfit`.
- `new_item` (dict): The selected listing dictionary so the fit card can mention the item name, platform, price, or vibe.

**What it returns:**
A single caption string ready to show the user, such as `"thrifted this faded band tee off depop for $22 and honestly it was made for my wide-legs 🖤 full look in my stories"`. The output should feel like a short social caption, not a structured object.

**What happens if it fails or returns nothing:**
If `outfit` is missing, empty, or clearly incomplete, the agent should not fabricate a caption. It should stop and show a message that the styling step failed and that it needs a valid outfit suggestion before generating the fit card.

## Planning Loop

**How does your agent decide which tool to call next?**
The agent starts by parsing the user query into `description`, `size`, and `max_price`, then calls `search_listings(description, size, max_price)`. If the returned list is empty, it sets `session.error_message = "No listings matched your search. Try a broader item description, a different size, or a higher budget."` and returns immediately.

If search results exist, the agent stores `session.selected_item = results[0]` and checks the wardrobe state. If `session.wardrobe.items` is empty, it sets `session.error_message = "I found a listing, but I need wardrobe items to suggest an outfit."` and returns without calling `suggest_outfit`.

If the wardrobe has items, the agent calls `suggest_outfit(new_item=session.selected_item, wardrobe=session.wardrobe)` and stores the returned string in `session.outfit_suggestion`. If the suggestion is empty or missing, it stops with a styling error message. Otherwise it calls `create_fit_card(outfit=session.outfit_suggestion, new_item=session.selected_item)`, stores the result in `session.fit_card`, and ends by returning the selected item, outfit suggestion, and final fit card to the user.

---

## State Management

**How does information from one tool get passed to the next?**
The session keeps the user query, parsed search filters, the current wardrobe, and the latest outputs from each tool. `search_listings` writes `session.search_results`, the chosen first result is copied to `session.selected_item`, `suggest_outfit` writes `session.outfit_suggestion`, and `create_fit_card` writes `session.fit_card`.

The same `selected_item` object is passed forward unchanged from search to outfit generation to fit-card creation so the later tools can reuse the listing’s title, price, platform, and style tags. The wardrobe is also passed unchanged from session state into `suggest_outfit`, using `get_example_wardrobe()` for a sample user or `get_empty_wardrobe()` when testing the new-user path.

## Error Handling

For each tool, describe the specific failure mode you're handling and what the agent does in response.

| Tool | Failure mode | Agent response |
|------|-------------|----------------|
| search_listings | No results match the query | Tell the user, "I couldn’t find anything matching that search." Then suggest one or two concrete adjustments such as removing the size filter, raising the max price, or using a broader description, and stop the flow. |
| suggest_outfit | Wardrobe is empty | Tell the user, "I found an item, but I need some wardrobe pieces to build an outfit." Ask them to add wardrobe items or use the example wardrobe for testing, then stop before calling `create_fit_card`. |
| create_fit_card | Outfit input is missing or incomplete | Tell the user, "I couldn’t build the fit card because the outfit suggestion is missing." Return the error without inventing a caption so the upstream styling step can be fixed first. |

## A Complete Interaction (Step by Step)

Write out what a full user interaction looks like from start to finish — tool call by tool call. Use a specific example query.

**Example user query:** "I'm looking for a vintage graphic tee under $30. I mostly wear baggy jeans and chunky sneakers. What's out there and how would I style it?"

FitFindr first parses the query into `description="vintage graphic tee"`, `size="M"`, and `max_price=30.0`, then calls `search_listings(description, size, max_price)`. If search returns no results, it stops and tells the user to broaden the search; if search returns matches, it chooses the first result and continues.

**Step 1:**
Call `search_listings(description="vintage graphic tee", size="M", max_price=30.0)`.

**Step 2:**
`search_listings` returns three matching listings sorted by relevance, and the agent stores the top result as `selected_item = "Faded Band Tee — $22, Depop, Good condition"`.

**Step 3:**
Call `suggest_outfit(new_item=selected_item, wardrobe=<user's wardrobe>)`. The wardrobe can be the sample wardrobe from `get_example_wardrobe()` during testing, or the user’s real wardrobe if it has already been loaded into session state.

**Step 4:**
Call `create_fit_card(outfit=<suggestion>, new_item=selected_item)` using the styling sentence returned from step 3 and the chosen listing.

**Final output to user:**
The user sees the outfit suggestion plus the fit-card caption, for example: `Pair this with your wide-leg jeans and platform Docs for a classic 90s grunge look. Roll the sleeves once and tuck the front corner slightly for shape.` followed by `thrifted this faded band tee off depop for $22 and honestly it was made for my wide-legs 🖤 full look in my stories`.
